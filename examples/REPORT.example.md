## Confirmed Findings

### 1. High — Authentication bypass via missing ownership check

**Summary:** An endpoint accepts a resource ID from the caller and performs the action without verifying that the authenticated user owns or is allowed to access that resource.

**Impact:** A low-privilege authenticated user can act on resources belonging to other users.

**Evidence location:** `src/api/handlers/resource.ts` (around the ownership check that is missing).

**Recommended fix:** Add an explicit ownership or permission check at the last trusted decision point before the side-effect. Prefer a single authoritative helper that all mutating routes must call.

---

### 2. Medium — Sensitive data in error responses

**Summary:** Certain error paths return internal exception details that include fragments of user data or internal identifiers.

**Impact:** Information disclosure that can aid further attacks or leak private data.

**Recommended fix:** Map internal errors to safe, generic client messages. Log the detailed error only server-side.
